# 头像转九头身角色设定图

## 执行契约

- 把“用户选择本技能或所属插件，并上传一张可用头像”视为完整生成指令。不要要求再次确认，不要先展示提示词，不要让用户补填表单。
- 默认生成一张完整的16:9设定图：两张放大的脸部特写＋三张同比例全身图。整张图一次生成，保持同一个人物、发型、衣服、材质和照明。
- 采用内置图像生成工具，例如当前环境提供的 `image_gen`。只使用工具实际公开的参数。没有图像生成能力或调用失败时，如实说明，不以一段提示词冒充已完成的图片；不要擅自切换到付费外部服务、API或CLI。
- 用户本次明确指定的服装、背景、比例或输出模式覆盖对应默认值，其余设定继续保持；不要累加互相矛盾的新旧要求。用户明确只要提示词时，只交付所需提示词。
- 人物面部身份、年龄观感与自然结构优先。将九头身和数值点位作为生成及检查目标，不承诺逐像素精准、绝对身份一致，或从单张头像还原未展示的真实身材与背面。

## 1. 读取头像

1. 优先使用本轮上传的头像；用户明确指向前文某张图片时使用该图。不要从其他会话、记忆、网上搜图或无关人物补足身份。
2. 一张图中应有明确的目标人物。多张同一人的参考可辅助理解，但以用户指定的主头像锁定面部。若包含多名不同人物且目标不明，只问一次需要使用哪位，不混合人脸。
3. 对本地路径先使用 `view_image` 查看；对已在当前对话可见的上传图片直接读取视觉内容。没有可访问头像或脸部完全不可辨认时，请用户上传一张清楚的头像；不要虚构图片内容。
4. 识别并保留可见的眉眼鼻口、脸型、下巴、发际线、发色、发型、妆容、肤色及年龄观感。不要识别人物姓名、推断敏感身份或自行美化成另一张脸。

## 2. 构造生成请求

1. 每次生成前读取 [references/generation-prompt.md](references/generation-prompt.md)，使用其中完整提示词。该文件是视觉约束的唯一来源，不随意省略数值、视角或布局要求。
2. 给输入图标注角色：主头像是唯一面部身份依据；其他参考仅在用户指定范围内辅助服装或风格。补充少量实际可见的发型或妆容特征即可，不重复堆叠形容词。
3. 参考图未展示的身体和后脑发型做保守、一致的设计补全，并将同一补全方案用于全部视图。不要声称补全是人物真实外观。
4. 默认服装为白色背心式分体泳装（白色背心式泳衣上装、白色平口泳裤）和简洁高跟凉鞋；所有视图使用同一款式。不加入性感姿态或夸张性征，不改变参考人物的年龄观感；遇到年龄与成人造型目标冲突时，优先保留合龄外观并遵循当前图像安全规则。
5. 保持默认中性灰色背景不透明。16:9、九头身和高品质写进提示词；不得捏造工具不存在的尺寸、seed、身份锁定或精确骨骼控制参数。

## 3. 直接生成

- 默认调用一次图像生成工具，生成一张包含全部五个视图的完整图片；不拆成五张独立人像再假称为一致的设定图。
- 将原始头像实际传入工具作为参考，不能只发送对头像的文字描述。
- 若当前接口提供 `referenced_image_paths`，且所有目标参考都有本地路径，使用这些路径；否则按接口文档使用能够覆盖相关图片的最小 `num_last_images_to_include`。两个机制不可同时使用。不能覆盖所需参考时，请用户重新附图。
- 仅包含必要参考；若接口不可避免地包含其他图片，在请求中明确各图作用，并以指定头像为唯一面部身份依据。
- 等待工具真正完成，按当前接口支持的方式展示图片。例如在代码模式中使用 `generatedImage(result)`；不要打印图像base64或内部执行数据。

## 4. 检查并交付

在结果可供查看时进行一次视觉检查，重点检查：

- 左侧上下两张特写、右侧正面／向画面左侧的90度侧面／180度背面，共五个视图。
- 同一人物的五官、脸型、肤色和发型一致；侧面不转头，背面不回头。
- 三张全身比例尺和关键高度一致，明显修长九头身，头顶至鞋底完整入镜；脸部特写的放大不改变全身头部比例。
- 白色泳装、高跟凉鞋的款式一致，姿态中立、结构自然；严格侧面允许远侧肢体被遮挡。
- 灰底柔光、分隔线细窄，无文字、水印、尺寸标注、重复肢体或明显畸形。

发现明确的视角错误、缺少视图、严重身份漂移、截断或畸形时，可进行至多一次有针对性的修正；同时保留原始头像为身份参考，避免只用有漂移的生成图继续迭代。不要为了难以测准的小幅比例差异无限重试。无法查看或测量时，不声称已完成相应检查。

成功后以图片为主要交付，不主动附上整段提示词或冗长解释。实际存在重要偏差时用一句话说明，不声称已经精准满足未验证的比例。仅在用户要求提示词、拆分图、修改或说明时追加对应内容。
